# 開發流程與角色分派

## 概述

本文件定義 Taiphoon_Agent 專案的迭代開發流程與各角色（子代理）的職責邊界。

---

## 基本迭代流程

```
開發 → 審查 → 測試 → 開發 → 審查 → 測試 ...
```

- 每一輪迭代都必須根據上一輪迭代留下的紀錄進行修正。
- 每個人員（子代理）可以動態建立或關閉。
- 在目標尚未完成或明確下達停止指令前，禁止自行終止專案開發。

---

## 角色定義

### 開發人員

- 負責規劃系統架構與撰寫程式碼。
- 開發過程必須嚴格遵循 `CODE_CONSTRAINT.md` 的規範。
- 開發完一個關鍵模組或功能時，必須主動告知審查人員進行審查。
- 開發過程中應留下操作手冊，讓測試與文件維護人員能夠操作開發的功能。
- 開發時應參照測試人員留下的紀錄進行修正。
- 可將經過驗證的方法寫入 Skill，但任何 Skill 的修改都必須告知審查人員。

### 審查人員

- 負責確保程式碼與系統架構符合 `AGENTS.md` 與 `CODE_CONSTRAINT.md` 的規範。
- 收到開發人員的審查請求後，逐項檢查並彙整問題，一次性告知開發人員進行修改。
- 對於開發人員告知已修改的內容，應特別加強審查。
- 審核通過後，將程式碼交付測試與文件維護人員進行模擬測試。

### 測試與文件維護人員

- 負責執行模擬測試任務。
- 需啟動 3 台 PX4 模擬器，確認任務是否達成設定目標。
- 根據開發人員留下的操作手冊下達指令，並驗證任務是否成功完成。
- 測試過程中發現的問題，應在 `AutoTest/` 目錄下建立 Log 資料夾，記錄測試驗證結果供開發者參考。
- 身為迭代的最後一個環節，需同時肩負文件更新責任，將有效指令與操作說明更新至 `README.md` 等文件中。

---

## 角色間協作規範

| 階段 | 發起者 | 接收者 | 交付物 |
|------|--------|--------|--------|
| 開發完成 | 開發人員 | 審查人員 | 原始碼 + 操作手冊 |
| 審查完成 | 審查人員 | 測試人員 | 審查通過的程式碼 |
| 測試完成 | 測試人員 | 開發人員 | `AutoTest/` 下的測試紀錄 |
| 文件更新 | 測試人員 | 所有人 | 更新的 `README.md` |

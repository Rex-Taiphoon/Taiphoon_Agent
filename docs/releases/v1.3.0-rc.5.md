## 使用方式

- Ubuntu 22.04 安裝 Docker Engine 與 Compose plugin；Windows／macOS 安裝並啟動 Docker Desktop 的 Linux containers。
- 下載符合 CPU 架構的完整套件並解壓縮；樹莓派選 `linux-arm64`，Apple Silicon 選 `macos-arm64`。
- Windows 執行 `./taiphoon_agent.exe start`；macOS／Linux 執行 `./taiphoon_agent start`。
- 模擬前若 `Taiphoon_Net` 不存在，先執行 `docker network create Taiphoon_Net`。
- Windows／macOS 模擬啟動成功後，依畫面列出的參數啟動同機的 Taiphoon_QGCS；多網卡時在 `settings.ini` 指定 `lan_address`。
- 進階設定見套件內的 `README.md`。重新起飛或 Agent 重新啟動後須重新下達編隊命令。

## 主要變更

相較於 v1.3.0-rc.4：

- 修正先移動再下達編隊時，初次編隊中心沿用目前飛行高度而與編隊高度疊加的問題；編隊高度一律以 Home 為基準。
- 修正 Agent 在 FormationEpoch 切換途中關閉時，存活成員停在不同 parent 而互相拒絕、永久維持 hold 的問題；sequence 較新的 epoch 可成為候選。
- 新增候選 FormationEpoch 15 秒未全員 `ADOPTED` 即丟棄並以存活成員重新提案；含已確認離線成員的 epoch 不採用。
- 調整飛行中重新啟動的 Agent 需重新下達 `FORMATION_*` 才會加入，期間其他成員維持目前編隊與槽位。
- 新增 Windows／macOS Docker Desktop 模擬時，原生啟動器自動取得主機區網 IPv4，為每台 Agent 產生專屬單播埠段的 CycloneDDS 設定，供同機原生 Taiphoon_QGCS 連線，並印出 QGCS 啟動參數。
- 新增開發用 `docker-compose.local-qgcs.yml` 與 `AutoTest/scripts/start_local_qgcs_agents.ps1`，在 Windows 開發環境啟動可供本機 QGCS 連線的 Agent。
- Linux Docker Engine 模擬與實機部署的網路行為維持不變。

## 驗證與限制

- 新增編隊中心高度與 FormationEpoch 重組／重新加入的純邏輯單元測試，以及啟動器單播 DDS 設定的單元與整合測試。
- 操作者已於多機模擬確認本版編隊功能正常。
- Docker Desktop 單播模式下 Agent 間 DDS 資料經主機埠轉送，只用於 GCS 連線與功能測試，不作為編隊時序驗證。
- 硬體、樹莓派／macOS 現場飛行仍需驗收；macOS 套件尚未公證，ARM64 的 PX4 模擬需要 Docker 支援 AMD64 CPU 模擬。

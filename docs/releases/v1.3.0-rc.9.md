## 使用方式

- Ubuntu 22.04 安裝 Docker Engine 與 Compose plugin；Windows／macOS 安裝並啟動 Docker Desktop 的 Linux containers。
- 下載符合 CPU 架構的完整套件並解壓縮；樹莓派選 `linux-arm64`，Apple Silicon 選 `macos-arm64`。
- Windows 執行 `./taiphoon_agent.exe start`；macOS／Linux 執行 `./taiphoon_agent start`。
- 模擬前若 `Taiphoon_Net` 不存在，先執行 `docker network create Taiphoon_Net`。
- 實機多機飛行（樹莓派）第一次需在主機設定對時：uav_1 執行 `sudo bash setup_time_sync.sh master`，
  其他機執行 `sudo bash setup_time_sync.sh client <uav_1 IPv4>`（腳本位於 Linux 平台包根目錄）。
  每次飛行先開 uav_1，再開其他機；單機飛行可在 `settings.ini` 設定 `time_sync=off`。
- 實機沒有障礙物感測器時，MOVE 與編隊移動需要在 `settings.ini` 設定 `obstacle_source=explicit_empty`。
- **飛控韌體需為 PX4 v1.14 以上**：本版送往 PX4 的訊息以 `timestamp = 0` 交由 PX4 接收蓋章，依賴 v1.14 起的
  uXRCE-DDS 行為。實機飛行前請確認飛控韌體版本。
- 實機飛行前請檢查 PX4 `MC_AIRMODE`（建議 0 或 1）與 `MC_YAWRATE_MAX`（需大於等於 Agent 的偏航限速）。
- 進階設定見套件內的 `README.md`。重新起飛或 Agent 重新啟動後須重新下達編隊命令。

## 主要變更

相較於 v1.3.0-rc.8：

- **修正懸停中被 PX4 誤判 Offboard 失聯而返航**：Offboard 心跳、軌跡設定點與 VehicleCommand 原本帶 Agent 主機時間，
  經 uXRCE-DDS 時間同步換算後，偏移估計跳動時可能落後 PX4 時鐘超過 `COM_OF_LOSS_T`（1 秒），即使心跳持續送達
  也會觸發 failsafe RTL。現改為 `timestamp = 0`，由 PX4 以接收時間蓋章，不再受換算影響。
- **降落後直接解鎖起飛**：RTL 降落後送出的 Hold 模式命令參數錯誤（main mode 8，PX4 回覆 `Unsupported main mode`），
  PX4 會停在缺少心跳的 Offboard 而預檢失敗，必須先送 `MODE_OFFBOARD` 才能再解鎖。現修正為 Hold
  （AUTO + LOITER），且 RTL、LAND、DISARM 或自動上鎖後，PX4 只要停在 Offboard 而 Agent 沒有 Offboard
  session，就會切到 Hold。
- **ARM／TAKEOFF 自動進入 Offboard**：在地面沒有 Offboard session 時，`ARM` 先自動完成 Offboard 進入流程再解鎖；
  `TAKEOFF` 等 PX4 回報已解鎖才起飛（3 秒內未解鎖即取消）。Offboard 進入期間收到的 `ARM`／`TAKEOFF` 改為排隊，
  不再打斷預送心跳。空中行為不變。原本的 `MODE_OFFBOARD` → `ARM` → `TAKEOFF` 流程仍可使用。
- **ARM 被拒處理**：PX4 拒絕解鎖時，Agent 輸出 WARN（含 VehicleCommandAck result）、停止 Offboard session 並回到
  IDLE，不再把狀態留在 ARMED。拒絕原因目前只出現在 Agent 日誌，尚未回報至 QGCS。
- **規劃器預算與逾時**：`optimizer_time_budget_ms` 預設由 50 ms 放寬為 70 ms（仍低於 10 Hz 規劃週期）；時空 A*
  最多使用 60% 預算，保證最佳化分得到時間；逾時或迭代用盡時回傳過程中成本最低且滿足硬性間距的解，仍須通過
  動力學與安全驗證；梯度計算逐軸檢查預算，避免超時。連續規劃失敗 20 次時升級為 ERROR 日誌，不改變控制行為。
- **單元測試穩定化**：規劃器與時空 A* 的正確性測試改用寬鬆預算，只由迭代或節點上限終止，結果不再隨 CPU 負載變動。
- `msg/` 介面未變更，可與 rc.8 的 Taiphoon_QGCS 共用；同一機群仍建議使用相同版本的 Agent。

## 驗證與限制

- 開發容器 `colcon test` 361 項全數通過（新增 Offboard 時間戳、降落後 Hold、自動 Offboard、ARM 被拒、
  最佳 hard-clear 解等測試）；規劃器與時空 A* 測試各重複 20 次、BasicController 測試重複 5 次皆通過。
- 三機 PX4 SITL（Docker Desktop 開發 compose，搭配 Taiphoon_QGCS）：
  - 11.5 分鐘懸停與 20 次編隊切換無 failsafe；PX4 ulog 中 `offboard_control_mode` 時間戳 0 次倒退
    （修正前同情境倒退 5 次並觸發 RTL）。
  - 不先送 `MODE_OFFBOARD` 直接 `ARM` → `TAKEOFF` 三機皆起飛；RTL 與 LAND 降落後 PX4 皆停在 Hold
    （nav_state 4）且預檢通過；降落後直接 `ARM` → `TAKEOFF` 三機皆重新起飛。
  - 5 輪編隊切換三機規劃失敗 0 次（修正前同類測試出現逾時與無解）。
- 本版 SITL 驗證使用開發 compose，未以樹莓派相同的 `runtime-entrypoint.sh` 重跑完整回歸；排隊中的 `TAKEOFF`
  路徑只以單元測試驗證。
- 硬體、樹莓派／macOS 現場飛行仍需驗收；macOS 套件尚未公證，ARM64 的 PX4 模擬需要 Docker 支援 AMD64 CPU 模擬。
- 雲端 Release workflow 會在發布前重新建置五個平台並執行測試，未通過不會發布。

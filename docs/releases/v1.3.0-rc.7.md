## 使用方式

- Ubuntu 22.04 安裝 Docker Engine 與 Compose plugin；Windows／macOS 安裝並啟動 Docker Desktop 的 Linux containers。
- 下載符合 CPU 架構的完整套件並解壓縮；樹莓派選 `linux-arm64`，Apple Silicon 選 `macos-arm64`。
- Windows 執行 `./taiphoon_agent.exe start`；macOS／Linux 執行 `./taiphoon_agent start`。
- 模擬前若 `Taiphoon_Net` 不存在，先執行 `docker network create Taiphoon_Net`。
- Windows／macOS 模擬時，QGCS 在其他電腦者，先執行 `config` 選 sim 並填入該電腦 IPv4；啟動成功後依畫面列出的參數啟動 Taiphoon_QGCS（固定 participant index 50），該電腦需允許 UDP 7510／7511 入站。
- 進階設定見套件內的 `README.md`。重新起飛或 Agent 重新啟動後須重新下達編隊命令。

## 主要變更

相較於 v1.3.0-rc.6：

- 修正 Windows／macOS Docker Desktop 模擬（主機 QGCS 單播模式）下 Agent 之間互相看不到、各自組成單機編隊的問題。所有 Agent 公告同一主機 IP 時，CycloneDDS 會把同儕位址改寫成本機容器 IP；本版每台 Agent 另啟動 `dds_peer_relay`，把同儕封包轉給 `Taiphoon_Net` 上的對應 Agent 容器。不需要特權，實機與 Linux Docker Engine 不受影響。
- 新增燕行（V 字）編隊 `FORMATION_V_SHAPE <翼上間距> <高度>`：頂點朝 North，其餘機依序左、右交替排在後方兩翼，半角 45°；`FormationEpoch` 新增 `V_SHAPE=3`。
- 編隊槽位分配改以總移動距離最短為基礎；環形編隊另搜尋最低成本相位，成員減少時存活成員只做最短移動，不再整圈換位。
- 編隊至少需要 2 台穩定成員：少於 2 台時拒絕 `FORMATION_*`；編隊中只剩本機時解散並原地懸停。槽位距離小於 `formation_min_distance_m` 的參數（例如半徑過小）在命令階段即拒絕。
- `FormationEpoch.msg` 已變更，同一機群內的 Agent 與 Taiphoon_QGCS 請使用相同版本的介面，不要與 rc.6 以前的 Agent 混用。

## 驗證與限制

- 新增 `dds_peer_relay` 埠段規劃、燕行隊形、最短距離分配與單機解散的單元測試，降落整合測試改以 2 機編隊驗證；master 上的 CI 全數通過。
- Docker Desktop 模擬下多台 Agent 實際組成編隊、燕行隊形的多機飛行，待本版於多平台裝置驗收。
- Docker Desktop 單播模式只用於 GCS 連線與編隊功能測試，不作為編隊時序驗證。
- Taiphoon_QGCS 暫未提供 `FORMATION_VERT_LINEAR` 按鈕。
- 硬體、樹莓派／macOS 現場飛行仍需驗收；macOS 套件尚未公證，ARM64 的 PX4 模擬需要 Docker 支援 AMD64 CPU 模擬。

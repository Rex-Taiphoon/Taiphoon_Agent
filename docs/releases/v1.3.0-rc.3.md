## 使用方式

- Ubuntu 22.04 安裝 Docker Engine 與 Compose plugin；Windows／macOS 安裝並啟動 Docker Desktop（Linux containers）。
- 下載符合 CPU 架構的完整套件並解壓縮；樹莓派選 `linux-arm64`，Apple Silicon 選 `macos-arm64`。
- Windows 執行 `./taiphoon_agent.exe start`；macOS／Linux 執行 `./taiphoon_agent start`。
- 首次啟動會引導設定、自動校驗並載入內附映像；後續沿用保存設定。啟動後由操作者下達 Arm 與起飛命令。
- 進階設定見套件內的 `README.md`。

## 主要變更

相較於 v1.3.0-rc.1：

- 修正 Windows 載入大型映像清單時的堆疊耗盡問題。
- 修正 Docker 儲存方式差異造成的映像校驗失敗，支援以映像 ID 或檔案層確認內容。
- Docker Desktop 改為自動映射飛控與 DDS 的 UDP 埠，連接實機時可直接使用預設網路設定。
- 簡化啟動設定：`sim` 可選 1～4 組 PX4＋Agent，`deploy` 啟動單台 Agent，Wi-Fi 飛控預設 IP 為 `192.168.1.14`。
- 修正 Windows 從桌面開啟工具時找不到 Docker 的問題，新增標準安裝路徑搜尋。
- 修正開發模式的符號連結安裝相容性，工作區改用複製安裝。
- 修正 CI 暫存產物的讀取權限，讓後續步驟可正常上傳模擬驗證產物與平台套件。

## 驗證與限制

- CI：AMD64／ARM64 各 328 個 ROS2 測試與三組 CTest 通過；AMD64 單組／四組 PX4 模擬通過；Windows／macOS 啟動器編譯通過。
- Windows 完整套件：下載、載入映像、單組模擬、飛控狀態接收與停止驗證通過。
- 待驗收：樹莓派與 macOS 實機、Wi-Fi／外部 GCS 連線及現場飛行；macOS 套件尚未公證。
- ARM64 的 PX4 模擬需要 Docker 支援 AMD64 CPU 模擬。

## 使用方式

- Ubuntu 22.04 安裝 Docker Engine 與 Compose plugin；Windows／macOS 安裝並啟動 Docker Desktop 的 Linux containers。
- 下載符合 CPU 架構的完整套件並解壓縮；樹莓派選 `linux-arm64`，Apple Silicon 選 `macos-arm64`。
- Windows 執行 `./taiphoon_agent.exe start`；macOS／Linux 執行 `./taiphoon_agent start`。
- 樹莓派等 Linux／macOS 主機可在新套件目錄執行 `bash install.sh` 安裝或更新既有的 Agent（沿用 `settings.ini`，
  失敗時自動切回上一版）；實機首次安裝可用 `bash install.sh --yes --agent-id 2 --autostart`。
- 模擬前若 `Taiphoon_Net` 不存在，先執行 `docker network create Taiphoon_Net`。
- 實機多機飛行（樹莓派）第一次需在主機設定對時：uav_1 執行 `sudo bash setup_time_sync.sh master`，
  其他機執行 `sudo bash setup_time_sync.sh client <uav_1 IPv4>`（腳本位於 Linux 平台包根目錄）。
  每次飛行先開 uav_1，再開其他機；單機飛行可在 `settings.ini` 設定 `time_sync=off`。
- 實機沒有障礙物感測器時，MOVE、編隊移動與航點任務需要在 `settings.ini` 設定 `obstacle_source=explicit_empty`。
- **航點任務、事件與健康回報需搭配 Taiphoon_QGCS v1.3.0**；較舊的 QGCS 仍可使用原有的命令與編隊功能。
- **飛控韌體需為 PX4 v1.14 以上**，並輸出 `vehicle_status_v4`、`vehicle_command_ack_v1`（與 PX4 main 分支一致）。
  實機飛行前請確認飛控韌體版本。
- 實機飛行前請檢查 PX4 `MC_AIRMODE`（建議 0 或 1）與 `MC_YAWRATE_MAX`（需大於等於 Agent 的偏航限速）。
- 進階設定見套件內的 `README.md`。重新起飛或 Agent 重新啟動後須重新下達編隊命令。

## 主要變更

相較於 v1.3.0-rc.9：

### 新增

- **單機航點任務**：QGCS 以 `/uav_N_agent/mission/plan`（`WaypointMission`）上傳經緯度與高度航點，只載入不移動；
  確認 `mission/status` 為 `LOADED` 後送 `MISSION_START <mission_id>` 才開始，`MISSION_STOP` 中止並停在原地。
  航點由機上 planner 依序執行（含機間避碰與停留時間），GCS 斷線不影響執行。執行中收到其他命令、PX4 離開
  Offboard、落地或單段逾時都會中止任務，並在 `mission/status` 回報原因。
- **事件回報**：新增 `/uav_N_agent/events`（`AgentEvent`），回報命令無法解析或被拒絕、PX4 拒絕或逾時未回覆命令、
  PX4 資料中斷、預檢失敗、PX4 重新啟動與規劃器緊急煞停等事件，附代碼、等級與說明。
- **健康回報**：新增 `/uav_N_agent/health`（`AgentHealth`，1 Hz），回報 PX4 各項資料的更新時間、解鎖狀態與預檢結果；
  PX4 完全沒有資料時也照常發布，地面站可據此判斷連線狀態。
- **重新啟動飛控**：新增 `REBOOT_FC [force]` 命令，確認落地且上鎖時才送出 PX4 重新啟動；收不到 PX4 狀態時可用
  `REBOOT_FC 1` 強制送出（由 PX4 在解鎖時自行拒絕）。送出後 15 秒內不接受重複命令；PX4 重新連線後發布事件 305，
  Agent 清除任務、編隊與 Offboard 狀態並重建 PX4 座標換算。
- **install.sh 安裝與更新**：Linux／macOS 平台包的 `install.sh` 可首次安裝或替換既有部署（含舊版安裝與 systemd
  服務），先載入新版映像再停止舊版，新版啟動失敗時自動切回；`--autostart` 設定開機自動啟動，`--rollback` 手動切回。

### 修正

- **一字隊形切換燕行時的緊急煞停**：無人機距槽位 3 m 內時，planner 原本直接把 PX4 設定點跳到槽位而不避碰，
  一字 2.5 m 切換燕行 12 m 時兩機交叉、最近 0.07 m 並觸發緊急煞停。現改為先確認「目前位置 → 槽位」直線與同儕
  位置及未來 4 秒軌跡保持安全距離，否則繼續一般規劃；換成不同隊形時也不再沿用前一隊形的槽位分配。

### 介面

- `msg/` 新增 `AgentEvent`、`AgentHealth`、`MissionWaypoint`、`WaypointMission`、`WaypointMissionStatus`；
  既有訊息未變更。同一機群仍建議使用相同版本的 Agent。
- README 改為使用者產品頁，並補上 MIT 授權。

## 驗證與限制

- 開發容器 `colcon test` 442 項全數通過（新增航點任務、事件代碼、命令解析、REBOOT_FC 安全條件、編隊直接到位
  淨空等測試）。
- 單機 PX4 SITL：兩點航點任務依序 LOADED → RUNNING → DWELLING → RUNNING → COMPLETED，終點水平誤差 0.27 m；
  停止 PX4 後發布資料中斷事件（302、300），重新啟動 PX4 後發布狀態恢復（301）與重新啟動（305）事件，
  之後起飛並執行任務正常。
- 四機 PX4 SITL 搭配 Taiphoon_QGCS 完成航點任務、事件與健康回報整合測試；三機 SITL 搭配 QGCS 操作測試本版。
- 四機一字 2.5 m 切換燕行 12 m 重複 3 次：緊急煞停 0 次，最近機間距離 2.18 m。
- `REBOOT_FC` 在 PX4 SITL 一律被拒絕（DENIED），實際重新啟動飛控與 `force` 需在實機驗證。
- 自動上鎖瞬間 PX4 預檢可能短暫為失敗而發布一筆事件 303；地面站以 `health` 的預檢結果確認。
- 飛控輸出的訊息版本不同時，Agent 收不到 PX4 狀態與命令回覆，`health` 的對應更新時間維持 -1 並發布事件 300。
- `install.sh` 以替身在容器內驗證；真正的 systemd、映像載入與樹莓派效能需在目標機實測。Windows `install.ps1` 未變更。
- 硬體、樹莓派／macOS 現場飛行仍需驗收；macOS 套件尚未公證，ARM64 的 PX4 模擬需要 Docker 支援 AMD64 CPU 模擬。
- 雲端 Release workflow 會在發布前重新建置五個平台並執行測試，未通過不會發布。

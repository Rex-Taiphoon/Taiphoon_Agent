## 使用方式

- Ubuntu 22.04 安裝 Docker Engine 與 Compose plugin；Windows／macOS 安裝並啟動 Docker Desktop 的 Linux containers。
- 下載符合 CPU 架構的完整套件並解壓縮；樹莓派選 `linux-arm64`，Apple Silicon 選 `macos-arm64`。
- Windows 執行 `./taiphoon_agent.exe start`；macOS／Linux 執行 `./taiphoon_agent start`。
- 模擬前若 `Taiphoon_Net` 不存在，先執行 `docker network create Taiphoon_Net`。
- 實機多機飛行（樹莓派）第一次需在主機設定對時：uav_1 執行 `sudo bash setup_time_sync.sh master`，
  其他機執行 `sudo bash setup_time_sync.sh client <uav_1 IPv4>`（腳本位於 Linux 平台包根目錄）。
  每次飛行先開 uav_1，再開其他機；`taiphoon_agent timesync` 可在主機上單獨檢查（不是在 Agent 容器內）。
  單機飛行可在 `settings.ini` 設定 `time_sync=off`。
- 實機沒有障礙物感測器時，MOVE 與編隊移動需要在 `settings.ini` 設定 `obstacle_source=explicit_empty`，
  明確宣告場地淨空；預設 `none` 只能起飛、懸停、YAW 與降落。宣告後規劃器只做機間避碰，不會避開實體障礙物。
- 實機飛行前請檢查 PX4 `MC_AIRMODE`（建議 0 或 1）與 `MC_YAWRATE_MAX`（需大於等於 Agent 的偏航限速）。
- 進階設定見套件內的 `README.md`。重新起飛或 Agent 重新啟動後須重新下達編隊命令。

## 主要變更

相較於 v1.3.0-rc.7：

- **多機時間同步**：新增 `setup_time_sync.sh`（Linux 平台包）以 chrony 讓 uav_1 的樹莓派當時間主機，其他機向它對時，
  不需要 QGCS 或地面站。Linux 實機的 `taiphoon_agent start` 會先確認主機已對時（最多等待 60 秒），新增
  `taiphoon_agent timesync` 命令與 `settings.ini` 欄位 `time_sync`、`time_sync_max_offset_ms`（預設 50 ms）。
  Windows／macOS 實機只警告，模擬不檢查。
- **同儕時鐘差診斷**：各 Agent 以同儕軌跡估計時鐘差，每 30 秒輸出 `Peer clock offset`；超過
  `peer_clock_skew_warning_s`（預設 0.1 秒）輸出 WARN，超過 1 秒時規劃狀態改為指出時鐘差。只做診斷，不改變控制。
- **Offboard 不再因狀態短暫遺失而中止**：`VehicleStatus` 逾時門檻由 2 秒改為 5 秒並改用單調時鐘；PX4 明確離開
  Offboard（遙控接管或 failsafe）時仍立即停止輸出。修正 Wi-Fi 或 Docker Desktop 下狀態間隔約 3 秒就觸發
  Offboard 遺失 failsafe（RTL）的問題。
- **起飛不再轉向正北**：地面起飛時鎖定當下機頭航向；目標航向未設定時的防呆值改為目前航向。
- **偏航限速轉向**：`YAW` 與 `MOVE_POINT` 的 yaw 改為每 10 Hz 控制週期沿最短角度逼近，並提供 yawspeed 前饋，
  避免 PX4 Offboard 以 `MC_YAWRATE_MAX` 全速轉向造成瞬間拉高。新增參數 `yaw_rate_limit_deg_s`（預設 30°/s，
  `YAW 90` 約 3 秒），容器部署以環境變數 `BASIC_CONTROLLER_YAW_RATE_LIMIT_DEG_S` 設定。
- **實機障礙物地圖來源**：修正實機部署因沒有障礙物地圖，單機 MOVE、編隊移動與全體 MOVE 一律以
  `Required obstacle map is missing` 原地煞停的問題。新增 `settings.ini` 欄位 `obstacle_source`：預設 `none`
  維持原本行為；`explicit_empty` 由操作人員明確宣告場地淨空，Agent 發布空地圖，規劃器只做機間避碰。
  每次實機 `start` 顯示目前的障礙物來源；啟用時 runtime 健康檢查會確認空地圖節點存在。模擬模式不受影響。
- **編隊切換機間距離**：樹莓派 runtime 的 `reservation_lead_time_s` 由 0.5 秒改為 0.0 秒，與開發環境一致。
  以實機進入點模擬時，0.5 秒會讓一字切換燕行隊形的最近機間距離降至 1.36～2.30 m；0.0 秒時維持 3.6 m 以上。
- `msg/` 介面未變更，可與 rc.7 的 Taiphoon_QGCS 共用；同一機群仍建議使用相同版本的 Agent。

## 驗證與限制

- 開發容器 `colcon test` 352 項全數通過（新增 PX4 狀態新鮮度、同儕時鐘差、偏航限速與起飛航向等測試）；
  啟動工具 Linux ctest 3 項通過（含 `obstacle_source` 預設、宣告與非法值），Windows 本機建置確認 `timesync` 命令。
- 三機 PX4 SITL 以與樹莓派相同的 `runtime-entrypoint.sh` 執行：
  - `obstacle_source=explicit_empty` 回歸 10/10：起飛懸停、單機 MOVE、YAW（88.9° 用時 2.88 秒、高度偏差 0.014 m）、
    一字編隊、全體 MOVE、燕行隊形、取消編隊、時鐘偏差注入（各 Agent 皆輸出 `offset=+3.000 s` WARN）與全體降落，
    最近機間距離 3.61 m。
  - 預設 `none`：起飛懸停、YAW 與降落正常，MOVE 原地等待並回報 `Required obstacle map is missing`。
- 缺少 uav_1 的組合在模擬中正常：只有 uav_2 時 MOVE、YAW、降落正常且編隊命令被拒絕；uav_2 與 uav_3 完成完整編隊回歸。
  實機缺少 uav_1 時沒有時間主機，需改由其他機執行 `setup_time_sync.sh master`，或單機設定 `time_sync=off`。
- 三機 Docker Desktop 模擬搭配 Taiphoon_QGCS 已人工操作驗證，同儕時鐘差皆為 0.000 秒。
- 雲端 Release workflow 會在發布前重新建置五個平台並執行測試，未通過不會發布。
- SITL 的機體起始航向為北，起飛鎖定航向只能以單元測試驗證；chrony 實際跳時與多台樹莓派對時需在實機確認。
- SITL 中 PX4 會先落後約 10° 再以約 1.5 倍限速追上，結束時超越約 8° 後回穩，屬 PX4 姿態控制的反應。
- 硬體、樹莓派／macOS 現場飛行仍需驗收；macOS 套件尚未公證，ARM64 的 PX4 模擬需要 Docker 支援 AMD64 CPU 模擬。

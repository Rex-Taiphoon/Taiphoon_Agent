## 使用方式

- Ubuntu 22.04 安裝 Docker Engine 與 Compose plugin；Windows／macOS 安裝並啟動 Docker Desktop 的 Linux containers。
- 下載符合 CPU 架構的完整套件並解壓縮；樹莓派選 `linux-arm64`，Apple Silicon 選 `macos-arm64`。
- Windows 執行 `./taiphoon_agent.exe start`；macOS／Linux 執行 `./taiphoon_agent start`。
- 樹莓派等 Linux／macOS 主機可在新套件目錄執行 `bash install.sh` 安裝或更新既有的 Agent（沿用 `settings.ini`，
  失敗時自動切回上一版）；實機首次安裝可用 `bash install.sh --yes --agent-id 2 --autostart`。
- 模擬前若 `Taiphoon_Net` 不存在，先執行 `docker network create Taiphoon_Net`。
- 實機多機飛行（樹莓派）第一次需在主機設定對時：uav_1 執行 `sudo bash setup_time_sync.sh master`，
  其他機執行 `sudo bash setup_time_sync.sh client <uav_1 IPv4>`（腳本位於 Linux 平台包根目錄）。
  每次飛行先開 uav_1，再開其他機；單機飛行可在 `settings.ini` 設定 `time_sync=off`。
- 實機沒有障礙物感測器時，MOVE、編隊移動與航點任務需要在 `settings.ini` 設定 `obstacle_source=explicit_empty`。
- **地理圍籬需由地面站設定**：Agent 不再從啟動參數讀取圍籬；QGCS 支援圍籬設定前，Agent 不啟用圍籬，
  其餘功能可搭配 Taiphoon_QGCS v1.3.0 使用。
- **飛控韌體需為 PX4 v1.14 以上**，並輸出 `vehicle_status_v4`、`vehicle_command_ack_v1`（與 PX4 main 分支一致）。
  實機飛行前請確認飛控韌體版本。
- 實機飛行前請檢查 PX4 `MC_AIRMODE`（建議 0 或 1）與 `MC_YAWRATE_MAX`（需大於等於 Agent 的偏航限速）。
- 進階設定見套件內的 `README.md`。重新起飛或 Agent 重新啟動後須重新下達編隊命令。

## 主要變更

相較於 v1.4.0-rc.1：

### 新增

- **地理圍籬（地面站設定）**：QGCS 發布 `/uav_all_agent/geofence`（`Geofence`，WGS84 多邊形 3～64 個頂點、
  margin 0～10 m）設定或清除水平圍籬，飛行中可隨時更新；各機以 `/uav_N_agent/geofence/status`
  （`GeofenceStatus`）回報 DISABLED／PENDING／ACTIVE、接受或拒絕原因與目前位置是否在圍籬內。
  圍籬生效後，MOVE、編隊槽位與航點落在圍籬外一律拒絕，規劃出的軌跡全程留在圍籬內；不合法的新圍籬會被拒絕並保留原圍籬。
  圍籬不限制 PX4 返航、降落與遙控器操作。
- **圍籬更新取消越界工作**：新圍籬讓目前的編隊槽位、航點或移動目標落在外側時，取消並原地懸停，
  發布事件 403（`PLANNER_GEOFENCE_TARGET_CANCELLED`）；航點任務以原因 15（`REASON_GEOFENCE_UPDATE`）中止。
  已在圍籬外的無人機不會自動飛回，只允許往內移動。
- **停滯偵測**：飛往目標時若依進度重新規劃讓無人機停在原地（新候選軌跡走不到 20%，或 3 秒內離目標沒有再縮短
  0.2 m），planner 暫停依進度重新規劃，讓目前仍安全的軌跡飛完，每個週期仍做安全重驗證。

### 改善

- **小場域繞行**：最佳化器無法產生合格解時，安全的 seed 可直接採用；繞行路線安全但動力學超限時，
  逐步拉長時間（最多 2 倍）重新驗證。8×8 m 場域三機交叉不再逾時。
- **最小機間距離可設為 1.5 m**：以 `EGO_SWARM_PEER_COLLISION_MIN_DISTANCE_M`、`EGO_SWARM_FORMATION_MIN_DISTANCE_M`
  設定，預設仍為 2.0 m。

### 介面

- `msg/` 新增 `Geofence`、`GeofenceStatus`、`GeofenceVertex`；`PlannerStatus` 新增 `STATE_IDLE/RUNNING/HOLD/ERROR`
  常數，`WaypointMissionStatus` 新增 `REASON_GEOFENCE_UPDATE=15`，既有欄位排列不變。介面文件補上
  `PlannerStatus.state` 數值與 `reason` 分類。同一機群仍建議使用相同版本的 Agent。

## 驗證與限制

- 開發容器 `colcon test` 489 項全數通過（新增圍籬幾何、圍籬更新規則、停滯偵測、航點進度等測試）。
- 四機 PX4 SITL 飛行中更新圍籬 9/9 通過：編隊中縮小圍籬時 4 台發布 403 並懸停；移動與航點任務中縮小圍籬時
  取消並停在圍籬內；圍籬外的新目標被拒絕；清除後恢復正常移動。
- 8×8 m 場域（長軸 143°）三機 SITL，圍籬由測試程式以地面站介面發布：2.0 m 間距編隊 1 次、交叉 2 次全數通過；
  1.5 m 間距編隊 3 次全數通過，交叉 5 次中 1 次實測最小機間距離 1.483 m，略低於設定值，原因是 PX4 追蹤誤差。
  planner 只保證計畫軌跡不低於設定值，不另外預留追蹤誤差。
- 四機 SITL 回歸測試通過；開發者另以 SITL 手動測試本版。
- QGCS 圍籬設定介面仍在開發中；實機圍籬、1.5 m 間距與樹莓派現場飛行尚未驗收。
- macOS 套件尚未公證，ARM64 的 PX4 模擬需要 Docker 支援 AMD64 CPU 模擬。
- 雲端 Release workflow 會在發布前重新建置五個平台並執行測試，未通過不會發布。

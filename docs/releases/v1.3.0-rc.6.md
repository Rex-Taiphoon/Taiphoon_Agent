## 使用方式

- Ubuntu 22.04 安裝 Docker Engine 與 Compose plugin；Windows／macOS 安裝並啟動 Docker Desktop 的 Linux containers。
- 下載符合 CPU 架構的完整套件並解壓縮；樹莓派選 `linux-arm64`，Apple Silicon 選 `macos-arm64`。
- Windows 執行 `./taiphoon_agent.exe start`；macOS／Linux 執行 `./taiphoon_agent start`。
- 模擬前若 `Taiphoon_Net` 不存在，先執行 `docker network create Taiphoon_Net`。
- Windows／macOS 模擬時，QGCS 在其他電腦者，先執行 `config` 選 sim 並填入該電腦 IPv4；啟動成功後依畫面列出的參數啟動 Taiphoon_QGCS（固定 participant index 50），該電腦需允許 UDP 7510／7511 入站。
- 進階設定見套件內的 `README.md`。重新起飛或 Agent 重新啟動後須重新下達編隊命令。

## 主要變更

相較於 v1.3.0-rc.5：

- 新增 Windows／macOS Docker Desktop 模擬可指定其他電腦的 Taiphoon_QGCS IPv4（`dds_peers`）。每台 Agent 會主動向該電腦固定 participant index 50 的 discovery 埠（domain 0 為 7510）送出探索，解決其他電腦的 QGCS 在 3 台以上模擬時看不到第 3、4 台 Agent 的問題。
- `config` 選 sim 時詢問其他電腦的 QGCS IPv4；GCS IPv4 提示輸入 `-` 可清除舊值；模擬模式拒絕 `127.x`。
- 啟動成功後另列出其他電腦 QGCS 的啟動參數（不含 `--external-address`）。
- 原本送往同機 QGCS（`host.docker.internal`）的探索、主機埠映射、Linux Docker Engine 模擬與實機部署維持不變。
- 舊設定中殘留的 `dds_peers` 在 Docker Desktop 模擬會開始生效；不需要時請以 `config` 清除。

## 驗證與限制

- 新增啟動器單元測試（外部 GCS peer、domain 平移、拒絕 loopback、Linux 模擬不受影響）與整合測試（實際 CLI 產生的設定與啟動參數），Linux 開發容器內全數通過。
- 其他電腦 QGCS 連線 3 台以上模擬 Agent 的實際互通，待本版於多平台裝置驗收。
- Docker Desktop 單播模式下 Agent 間 DDS 資料經主機埠轉送，只用於 GCS 連線與功能測試，不作為編隊時序驗證。
- 硬體、樹莓派／macOS 現場飛行仍需驗收；macOS 套件尚未公證，ARM64 的 PX4 模擬需要 Docker 支援 AMD64 CPU 模擬。
